# 数据采集 SOP

## 适用场景
- 用户要求收集公开新闻、监管公告、行业资料、舆情或竞品信息；
- 需要把网页内容转成结构化数据，供后续分析、回测或审批材料引用；
- 需要保留来源 URL、抓取时间与原始快照，保证可追溯。

## 执行步骤

1. **明确目标与字段**
   - 确认主题、时间范围、地域/语言、需要的字段；
   - 如果用户没说清，先按最小可行字段采集：标题、来源、URL、发布时间、正文摘要。

2. **发现来源**
   - 调用 `web_search`，用 2~3 组不同关键词；
   - 优先官方/监管/权威媒体，其次行业媒体；
   - 排除明显无关、重复、低质聚合页。

3. **抓取正文**
   - 调用 `web_fetch`，一次只抓一个 URL；
   - 单页正文可能被截断，关键结论要回到原文核对；
   - 记录失败原因（超时、403、内容类型不支持、域名限制）。

4. **结构化落库**
   - 调用 `dataset_write` 写入 `/workspace/data/dataset_<序号>.json`；
   - 每条记录至少包含：`title / url / source / fetched_at / excerpt`；
   - 原始正文写入 `/logs/web/`，数据集只放摘要，避免文件过大。

5. **质量校验**
   - 去重：同一 URL、同一标题只保留一条；
   - 时间：确认发布时间在用户要求的时间窗内；
   - 覆盖：来源数量是否足够，是否只有单一立场；
   - 标注「已证实 / 推测 / 未验证」。

6. **输出报告**
   - 写入 `/reports/data_collection_<序号>.md`；
   - 包含：查询词、来源表、成功/失败数、数据限制、合规说明；
   - 回传主 Agent 的内容只保留摘要 + 数据集/报告路径。

## 合规红线
- 不抓取登录后、付费墙、隐私数据或明确禁止抓取的页面；
- 遵守目标站点 robots/服务条款与访问频率，不做高频并发抓取；
- 不绕过验证码、不伪造身份、不使用泄露凭证；
- 引用内容保留来源 URL 与抓取时间，避免版权与溯源问题；
- 涉及个人信息时先脱敏，不把原始 PII 写入数据集。

## 失败处理
- 搜索不可用：如果用户给了 URL 就直接抓；否则回退内部规则库并明确标注；
- 全部抓取失败：输出失败原因与建议（换来源、稍后重试、改用官方 API）；
- 内容类型不支持：记录 content-type，不要强行解析二进制。
